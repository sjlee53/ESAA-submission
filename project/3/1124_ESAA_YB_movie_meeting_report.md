## 2. 이번 주에 한 것

### (1) 베이스라인 제출 — 기준점 확보

점수를 올리는 것이 목적이 아니라 **교차검증 점수와 리더보드 점수가 어떻게 대응하는지 확인**하는 것이 목적이었다. 이 대응을 모르면 앞으로 무엇을 바꿔도 좋아졌는지 판단할 수 없다.

구성은 타깃 `log1p` 변환 + 장르·관람등급 원-핫 + 배급사 빈도 인코딩 + CatBoost(시드 3개 평균)다. 코드는 [`baseline_catboost.py`](baseline_catboost.py)에 있다.

미니 프로젝트(1)의 EDA 노트북 네 개(총 330셀)에 **`test`라는 단어가 한 번도 나오지 않는다.** 그때는 데이터 이해가 목적이라 train만 봐도 됐지만, 이제는 test에 예측값을 내야 한다. 노트북은 [`1124_ESAA_YB_movie_test_EDA.ipynb`](1124_ESAA_YB_movie_test_EDA.ipynb)에 있다.

## 3. 확인된 것

### (1) 리더보드 점수는 흥행작 몇 편이 결정한다

교차검증 오차 제곱합의 **61.8%를 상위 10편이 만든다.** 실제 관객 200만 미만인 540편만 떼어 재면 RMSE가 484,537로, 리더보드 7~40위 구간(47만~50만)과 겹친다.

test에는 명량·베테랑·군도·사도·신세계가 들어 있고, 우리 모델은 이들을 크게 낮춰 잡았다.

| 영화 | 예측 | 실제 (공개 기록) | RMSE 기여 (오차÷√243) |
|---|---|---|---|
| 베테랑 | 2,483,174 | 약 1,340만 | 약 70만 |
| 명량 | 12,343,100 | 약 1,760만 | 약 34만 |
| 군도 | 5,202,168 | 약 480만 | 약 3만 |

**두 편이 나머지 241편을 합친 것보다 크다.** 리더보드 120만의 대부분이 여기서 나왔다.

### (2) 이건 모델을 바꿔서 풀 수 없다

세 가지를 확인했다.

- **타깃 변환을 바꿔도 안 된다.** raw·log1p·sqrt·cbrt 모두 상위 5% 영화에 대해 실제의 **30~37%만** 예측한다. raw가 0.37로 가장 낫지만 전체 RMSE는 더 나쁘다.
- **큰 예측만 배수로 키우는 보정도 안 된다.** 최적값이 임계 30만·배수 1.2인데 개선폭이 4,237(0.3%)로 사실상 0이다.
- **애초에 변수가 구분을 못 한다.** train에서 `num_staff ≥ 500`인 23편의 관객수가 **317,505명부터 14,262,766명까지** 흩어져 있다. 규모가 크다는 것은 알아도 흥행 여부는 알 수 없다.

베테랑이 전형적인 예다. `num_staff` 579로 높지만 `dir_prev_bfnum`이 **97,469**로 기록돼 있어서, 모델이 보기에는 "감독 이전작이 10만 명도 안 든 액션 영화"다.

**결론: 주어진 11개 변수로는 110만~130만이 한계다.** 리더보드 47만~50만 구간은 흥행작을 ±30% 안으로 맞혀야 나오는 숫자인데, 이 피처로는 불가능하다.

### (3) test EDA에서 나온 것

- **결측은 결측이 아니다.** `dir_prev_bfnum` 결측(train 330건·test 136건)의 **100%가 `dir_prev_num == 0`인 행**이고 역도 성립한다. "감독의 이전 작품이 없다"는 사실의 표현이다.
- **범위 밖과 오류는 다르다.** train 범위를 벗어난 test 행 네 건 중 셋은 정상이다(198분·40분 상영시간, `dir_prev_num` 6). **「슈퍼레이서 엔지」의 상영시간 2015분 하나만 오류**다 — 개봉일이 2015-09-10이니 상영시간 칸에 개봉연도가 들어갔다.
- **감독과 배급사는 성격이 다르다.** test 243편 중 **63%가 train에 없는 감독**의 영화다. 타깃 인코딩을 넣으면 RMSE가 144만 → 162만으로 12% 나빠진다. 배급사는 미등장이 **15%**뿐이고 규모 자체가 신호라 빈도 인코딩이 작동한다.
- **배급사 표기가 흔들린다.** `(주)NEW`/`NEW`, `시네마달`/`시네마 달`/`(주)시네마달` 같은 식으로 **11개 그룹이 쪼개져 있다.** 괄호·공백만 정리하면 고유값이 204 → 191로 줄어든다.
- **분포는 train과 test가 거의 같다.** 그래서 **교차검증 점수를 리더보드의 대리 지표로 믿어도 된다.** 다만 액션이 test에 4%p 많은데, 액션은 평균 관객수가 두 번째로 큰 장르(220만)라 영향이 있다.
- **train에도 오류가 있다.** 「타부 : 금지된 사랑」의 `dir_prev_bfnum`이 17,615,314인데 본인 영화 관객수는 8명이다. 학습할 때 이 한 행이 관계를 정반대로 가르친다.

## 4. 공통 전처리 규칙 (확정)

전처리를 각자 다르게 하면 점수를 비교할 수 없다. **모델 담당자는 아래를 그대로 쓴다.**

| 항목 | 결정 | 근거 |
|---|---|---|
| `dir_prev_bfnum` 결측 | **0으로 채우고 `has_prev` 추가** | 결측 100%가 `dir_prev_num == 0` |
| test `time = 2015` | **애니메이션 중앙값 83분으로 교체** | 상영시간 칸의 개봉연도 입력 오류 |
| test 198분·40분, `dir_prev_num` 6 | **그대로 둔다** | 범위 밖일 뿐 오류가 아님 |
| train `dir_prev_bfnum` 1,761만 행 | **검토 대상** | 본인 영화 관객 8명. 관계를 정반대로 가르침 |
| `num_staff = 0` | **그대로 둔다** | 소규모 영화 신호 (관객 중앙값 996명) |
| 감독 | **타깃 인코딩 금지** | test 63% 미등장. RMSE 12% 악화 |
| 배급사 | **표기 정규화 후 빈도 인코딩** | 미등장 15%. 규모 자체가 신호 |
| 장르·등급 | **원-핫** | 범주 12개·4개, test 미등장 0% |
| 타깃 | **`log1p` 학습 → `expm1` 복원** | 1명~1,426만 범위. 155만 → 145만 |
| 스케일러·인코딩 fit | **train에서만** | 보는 것과 학습에 쓰는 것은 다르다 |

## 5. 결정 사항과 미결 사항

### 결정

- 공통 전처리는 위 표로 고정하고 `common.py` 하나로 만든다.
- 모델은 담당을 나눠 **같은 폴드·같은 시드**로 돌리고 결과를 한 표에 모은다.
- 제출은 하루 10회 제한이 있으므로 **교차검증에서 걸러낸 것만** 올린다.

### 미결 — 외부 데이터 사용 여부 (문의 중)

대회 규칙에는 "공공 데이터와 같이 누구나 얻을 수 있고 법적 제약이 없는 외부 데이터 허용"으로 적혀 있다. 과제 차원에서 써도 되는지는 **학회에 문의해 둔 상태**다. 답변에 따라 셋 중 하나로 간다.

| 안 | 내용 | 예상 점수 | 발표 측면 |
|---|---|---|---|
| **A** | 주어진 변수만 사용 | 110만~130만 | "왜 이 데이터로는 흥행작을 못 맞히는가"가 결론이 됨 |
| **B** | 외부 공개 데이터를 **피처로** 추가 (감독 과거 흥행 기록, 배우 동원력, 스크린 수 등) | 개선 여지 큼 | 피처 엔지니어링이 발표의 중심이 됨 |
| **C** | test 영화의 실제 관객수를 직접 사용 | 매우 높음 | 회귀 과제가 아니게 됨 |

**조 의견은 B다.** 베테랑이 안 잡히는 이유가 `dir_prev_bfnum`이 감독의 실제 이력을 담지 못해서이므로, 외부 데이터로 그 부분을 보강하는 것이 정확히 문제를 겨냥한다. 답변이 늦어지면 A로 진행하고 나중에 B를 얹는다.
