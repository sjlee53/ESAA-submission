## 1. 확정된 전처리

| 항목 | 결정 | 근거 |
|---|---|---|
| `is_white` | **넣는다** | 4개 변수가 red/white에서 상관 방향 반대. 승주·희경·경서가 각자 확인 |
| red/white 모델 | **통합** | 분리 0.6722 vs 통합 0.6687, 표준편차 안 |
| 결합 이산화황 | **추가** (`총 SO₂ − 유리 SO₂`) | 상관 0.717 포함 관계. 네 모델 전부 상승 |
| `density` | **넣는다** | 네 모델 중 셋에서 빼면 하락 |
| 이상치 | **삭제하지 않는다** | 희귀 등급 정보 손실. 트리는 이상치에 둔감 |
| 로그 변환 | **하지 않는다** | 트리는 값의 순서만 봄. 10개 조합 중 안정적 개선 없음 |
| 불균형 처리 | **네 모델 모두 미적용** | 11개 조합 중 미적용을 이긴 것 없음 |
| 상관 약한 변수 | **유지** | 7개 빼면 0.6687 → 0.6427 |
| 중복 행 | **유지** | 지우면 0.6687 → 0.5769. test의 30.3%가 train과 동일 |

**이 외에는 아무것도 하지 않는다.** 변환·이상치 처리·불균형 처리·중복 제거·변수 제거 모두 없음.

## 2. 확정된 검증 규칙

```python
from sklearn.model_selection import StratifiedKFold
cv = StratifiedKFold(5, shuffle=True, random_state=42)
```

- **같은 행 순서의 데이터**로 시작한다. `random_state`만 맞춰도 행 순서가 다르면 폴드가 달라진다.
- **평균과 함께 폴드별 5개 점수도 기록**한다.
- 기준선은 **0.4395** (전부 6점).
- 데이터에서 기준을 학습하는 처리(리샘플링·스케일링)는 **폴드 안에서**. `imblearn.Pipeline` 사용.
  `is_white`나 결합 SO₂ 같은 단순 계산은 미리 적용해도 된다.
- **최종 후보만** `StratifiedGroupKFold`로 한 번 더 확인한다.

```python
from sklearn.model_selection import StratifiedGroupKFold
feat = [c for c in train.columns if c not in ('index', 'quality')]
gid = train.groupby(feat, sort=False).ngroup()
cv_group = StratifiedGroupKFold(5, shuffle=True, random_state=42)
```

## 3. 불균형 처리 — 논의 경과

| 사람 | 주장 |
|---|---|
| 경서 | Random Oversampling 채택 (Macro F1 상승, Accuracy 거의 동일) |
| 민서 | `class_weight` 부여 |
| 승주 | 미적용 |

네 모델 × 세 처리를 전부 비교했다.

| 모델 | 미적용 | RandomOver | SMOTE | class_weight |
|---|---|---|---|---|
| 엑스트라 트리 | **0.6798** | −0.0044 | −0.0306 | −0.0040 |
| 랜덤포레스트 | **0.6735** | −0.0033 | −0.0346 | −0.0391 |
| XGBoost | **0.6540** | −0.0113 | −0.0171 | 지원 안 함 |
| LightGBM | 0.6513 | **+0.0022** | −0.0095 | −0.0047 |

미적용을 이긴 것은 LightGBM의 +0.0022 하나뿐이고 표준편차(±0.011) 안이다.
LightGBM은 네 모델 중 최하위라 최종 후보도 아니다.

모델마다 다르게 적용하지 않는 이유는 두 가지다. 조합이 늘어나면 **가장 높은 값을 고르는 것이
운을 고르는 것**이 되고, 소프트 보팅에서 **확률의 기준이 달라져** 앙상블이 망가진다.

→ **네 모델 모두 미적용으로 확정**

## 7. 세 번째 모델을 XGBoost로 정한 기준

XGBoost와 LightGBM은 정확도 차이가 0.0027로 사실상 동률이라, 네 가지 기준으로 비교했다.

| 기준 | XGBoost | LightGBM | |
|---|---|---|---|
| 일반 CV (리더보드 대리값) | **0.6540** | 0.6513 | XGB |
| 그룹 CV (처음 보는 와인) | 0.5385 | **0.5463** | LGBM |
| 안정성 (표준편차) | ±0.0123 | **±0.0107** | LGBM |
| 수행 시간 (5겹) | **17.3초** | 27.3초 | XGB |

두 기준은 LightGBM이 앞선다. 그럼에도 XGBoost를 택한 이유는, **대회 평가 산식이 Accuracy이고
리더보드는 겹침 30% 환경에서 채점하므로 일반 교차검증이 그 대리값**이기 때문이다.
수행 시간이 1.6배 빠른 것도 튜닝 반복에 유리하다.

> 교재에는 LightGBM이 더 빠르다고 나오지만, 5,497행 규모에서는 XGBoost가 더 빨랐다.
> LightGBM의 속도 이점은 데이터가 훨씬 클 때 나타난다.

**XGBoost 튜닝이 막히면 LightGBM으로 바꿔도 된다.** 두 모델이 동률이고 조건은 "3가지 이상"이다.

## 8. 결과를 말할 때 주의할 것

숫자를 다시 확인한 결과, 다음 네 가지는 **"효과가 있었다"고 말하면 과장**이다.

**① 결합 이산화황** — 네 모델 모두 올랐지만 각각은 +0.002~+0.005로 표준편차 안이다.
근거는 "네 번 모두 같은 방향"이라는 일관성뿐이다.
→ "포함 관계를 분리한다는 근거로 넣었고, 네 모델 모두 미세하게 올랐다"

**② red/white 통합** — 숫자만 보면 **분리가 0.6722로 통합 0.6687보다 높다.**
차이가 표준편차 안이라 데이터를 쪼개지 않는 쪽을 택한 것이다.
→ "분리가 0.003 높았지만 표준편차 안이라, 학습 데이터를 쪼개지 않는 통합을 택했다"

**③ XGBoost vs LightGBM** — 위 7절대로 기준을 밝힌다. "더 좋아서"가 아니다.

**④ 이상치 행 삭제** — 직접 비교하지 않았다. 캡핑(극단값 자르기)은 비교했고 효과가 없었다.

### 튜닝할 때 주의

교차검증 점수에는 중복으로 인한 몫이 약 10%p 섞여 있다. 그 점수를 최대화하면
`max_depth`를 깊게, `min_samples_leaf`를 1로 두는 쪽이 유리해 보일 수 있는데,
**학습 데이터를 외우는 방향**일 수 있다. 그래서 최종 후보는 반드시 그룹 검증으로 한 번 더 확인한다.
